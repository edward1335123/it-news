## 指摘一覧

必須の指摘はなし。

| # | 重要度 | 内容 | 対応 |
|---|---|---|---|
| 1 | 推奨 | iOS Safari・ホーム画面の PWA で、Blob と `<a download>` による .ics がカレンダー追加画面を開くか確かめていない。standalone 表示では無反応になる例がある | 一部対応: 「開く想定。実機で要確認」とコメントを直した。実機での確認はユーザーに依頼する。動かなければ、`navigator.share` で File を共有する方法などに切り替える（フェーズ4のあとで判断） |
| 2 | 推奨 | 保存した記事を shared の厳密な `articleSchema` で検証しているので、将来 Article に必須項目が増えると、お気に入り・後で読むが何も知らせずに消える | 持ち越し: フェーズ5で Article を変えるときに、保存用の緩いスキーマか移行処理を用意する |
| 3 | 推奨 | .ics の `URL:` 行が改行で壊れないのは zod が CR・LF を取り除くからで、空白を含む URL はそのまま出る | 対応済: `new URL(event.url).href` で正規化して出す。CRLF と空白を含む URL のテストを追加 |
| 4 | 任意 | 既読の判定に `in` を使っているので、`constructor` などのプロトタイプのキーが既読になる | 対応済: `hasRead`（`Object.hasOwn`）に置き換え、テストを追加 |
| 5 | 任意 | `onAuxClick` が右クリックでも発火し、メニューを開いただけで既読になる | 対応済: `button === 1`（中クリック）のときだけ既読にする |
| 6 | 任意 | 保存に失敗してもユーザーに知らせない。保存した記事の件数に上限がない | 持ち越し: 個人用で件数は少ない見込み。必要になったら上限と通知を追加する |
| 7 | 任意 | 終了日時がないイベントは、.ics では開始から1時間、終了の判定では当日の 24:00 までと、扱いが違う | 持ち越し: どちらも用途に合っている。必要なら DESCRIPTION に「終了時刻未定」と書き添える |
| 8 | 任意 | .ics に SEQUENCE・LAST-MODIFIED がなく、日時が変わったイベントを取り込み直しても更新されないカレンダーがある | 持ち越し: 優先度は低い |
| 9 | 任意 | TEXT の値から TAB も取り除いている | 対応不要: 害はない |
| 10 | 任意 | `.button` のルールが global.css の2か所に分かれている | 持ち越し: 表示には影響しない |
| 11 | 任意 | タブの矢印キー操作は作業項目にない | 対応不要: フェーズ2のレビューで持ち越した ARIA の指摘への対応 |

フェーズ2から持ち越した指摘の状態:

- 相対時刻の基準 `now` の更新: 対応済（`useNow` で、画面に戻ったときに更新する）
- タブの ARIA: 対応済
- 終了したイベントの表示: 対応済（`filterEvents` で隠す）
- タグがない記事の扱い: 引き続きフェーズ5で決める
