## 指摘一覧

| # | 重要度 | 内容 | 対応 |
|---|---|---|---|
| 1 | 必須 | Windows で、置き換え先の news.json を他のプロセス（起動中の開発サーバーなど）が開いていると、`rename` が EPERM で失敗し、`npm run collect:news` が止まる。手元で2回続けて再現した | 対応済: `writeAtomically` を追加。EPERM・EACCES・EBUSY のときは上書きコピーする。Linux（GitHub Actions）では従来どおり rename で置き換える |
| 2 | 必須 | `cleanUrl` が通す URL の一部（IP アドレス、`_` を含むホスト、`localhost`、末尾がドットのホスト）を、shared の `z.httpUrl()` が弾く。こうした URL が1件あるだけで、最後の `newsFileSchema.parse` が例外を投げ、news.json を更新できない | 対応済: `cleanUrl` の判定を `z.httpUrl()` に揃えた。加えて `toArticles` で `articleSchema` に通らない記事を捨てる。テストを追加 |
| 3 | 推奨 | 日時のない項目は、見つけた時刻を公開日時にする。そのため、30日で消えたあともフィードに残っていれば、新着として戻ってくる | 持ち越し: 日時のない項目を捨てるか、消した ID を覚えておくかを決める必要がある |
| 4 | 推奨 | タイムゾーンのない日時（`2026-10-23 10:00`）は、実行環境のローカル時刻として解釈される。`JST` 表記は解釈できない。GitHub Actions（UTC）では、国内の記事が9時間ずれるおそれがある | 持ち越し: 該当するフィードは今は確認できていない。フェーズ7で CI 上の実データを見て判断する |
| 5 | 推奨 | 応答サイズの上限を `content-length` でしか判定していない | 持ち越し: ストリームで読みながら数える。フェーズ7の前に入れたい |
| 6 | 推奨 | 計測用パラメータの削除と並べ替えのせいで、ユーザーが開く URL が元と変わる（`;` のエンコード、`?ref=` の削除など） | 持ち越し: 正規化した URL は ID・重複判定だけに使い、表示用には元の URL を残す。news.json の中身が変わるので、別に扱う |
| 7 | 推奨 | `redirect: 'follow'` なので、リダイレクト先が別のホストでも robots.txt を確認せず、間隔もあけない | 持ち越し: 今の48件で別ホストへのリダイレクトがあるかを調べてから決める |
| 8 | 推奨 | URL のテストが `text.test.ts` にあり、境界値が足りない | 一部対応: `url.test.ts` に分け、スキーマとの整合のテストを追加した。日時の境界値は 3・4 と一緒に扱う |
| 9 | 任意 | 二重にエスケープされたタグ（`&amp;lt;b&amp;gt;`）が `<b>` という文字として残る（React がエスケープするので XSS にはならない） | 対応済: 文字参照の復元とタグの除去を2回くり返す。テストを追加 |
| 10 | 任意 | `stripTags` の正規表現は、閉じていない `<script` が多いと遅くなりうる。タイトルの長さに上限がない | 持ち越し: 実害は確認できていない |
| 11 | 任意 | `mergeArticles` のコメント「先に公開された記事の related にまとめる」が、前回の記事が今回より新しいときの動作と合わない | 対応済: コメントを動作に合わせた |
| 12 | 任意 | 開発サーバーでモックの news.json を返すとき、sources.json は実データなので、モックにしかない情報源（`the-decoder`・`microsoft-msrc`）が ID のまま表示される | 持ち越し: 開発時の表示だけの問題 |
| 13 | 任意 | news.json は git 管理外なので、収集せずにビルドすると本番に news.json がない | 持ち越し: フェーズ7の CI で、収集をビルドの前に実行する |
| 14 | 任意 | robots.txt の User-agent を完全一致で照合している | 対応不要: 小文字にそろえて比べており、自分の製品トークンとの照合には十分 |

フェーズ3から持ち越した指摘（保存した記事を厳密な `articleSchema` で検証している）: このフェーズでは Article の形を変えていないので、今回も影響はない。Article を変えるときに対応する。
