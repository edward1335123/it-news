docs/PLAN.md のフェーズ $ARGUMENTS の実装をレビューする。会話はクリア済みの前提なので、まず次を読むこと。

1. CLAUDE.md、docs/SPEC.md、docs/PLAN.md を読む
2. 対象フェーズの状態が `実装済` でなければ、止めて報告する
3. `git log --oneline -20` で対象フェーズのコミットを特定し、差分を確認する

## 機械的な検証
- `npm run check` と `npm run build` を実行し、結果を記録する
- 画面を含むフェーズでは、開発サーバーを起動し、幅 375px で表示とレイアウト崩れを確認する（確認できる手段がある場合）

## 独立したレビュー
Agent ツールで general-purpose のサブエージェントを起動し、先入観のない立場でレビューさせる。依頼には次を含める。
- 対象フェーズの「作業」「完了条件」と、SPEC.md の関連する章
- 対象のコミット範囲
- 観点:
  - 完了条件をすべて満たしているか
  - SPEC からの逸脱がないか、範囲外の実装が混ざっていないか
  - バグ・境界値・エラー処理
  - セキュリティ（XSS、秘密情報の混入、外部入力の検証、依存パッケージ）
  - 型の安全性、テストの不足、可読性・重複
  - iPhone での使い勝手（画面を含むフェーズのみ）
- 指摘には重要度（必須 / 推奨 / 任意）、ファイルと行、理由、修正案を付けさせる

サブエージェントの指摘は自分でコードを読んで検証し、誤りは除外する。

## 修正と記録
1. 「必須」の指摘を修正し、`npm run check` を再実行して成功させる
2. 「推奨」は、範囲が小さく安全なものだけ修正する。それ以外は持ち越す
3. `docs/reviews/phase-N.md` に、検証結果、指摘の一覧（対応済 / 持ち越し / 対応不要とその理由）、ユーザーが確認すべきことを書く
4. 必須の指摘がすべて解消したら、PLAN.md の状態を `レビュー済` にする。解消できない場合は `実装済` のままにして理由を報告する
5. git にコミットする（`fix(phaseN): review fixes` の形式。末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` を付ける）
6. 結果を日本語で簡潔に報告し、次の手順（`/clear` してから `/phase N+1`）を示す
